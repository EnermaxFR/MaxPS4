# Sonic Mania GPU implementation status

Sonic Mania's local executable declares 113 `libSceGnmDriver` imports.
This is a static import inventory, not a trace proving all are executed.
Only NID/name metadata was used; no game code, shaders or assets are included
in this repository. The existing Pad/VideoOut demo is a CPU rasterizer and
does not provide a PS4 shader backend.

## Implemented GNM command writers

Five more imports now have real packet generation through checked guest memory:

| Function | NID | Output dwords |
| --- | --- | --- |
| sceGnmDrawIndexAuto | GGsn7jMTxw4 | 7 |
| sceGnmDrawIndex | HlTPoZ-oY7Y | 10 |
| sceGnmSetVsShader | gAhCn6UiU4Y | 29 |
| sceGnmSetPsShader350 | 5uFKckiJYRM | 40 |
| sceGnmSetVgtControl | cFCp0NX8wf0 | 3 |

The base-PS4 sequences, descriptor layouts, validation and NIDs follow the
pinned [shadPS4 GNM implementation](https://github.com/shadps4-emu/shadPS4/blob/91e6afa69b0a64b0afaa0281b80f8fbb0cd88136/src/core/libraries/gnmdriver/gnmdriver.cpp).
Neo behavior is not selected. These functions build PM4 in the caller's
buffer; success does not mean submission or GPU completion. Unsupported
functions remain unresolved instead of reporting successful work.

VS consumes seven register words, applies the permitted modifier mask, and
emits program address/resources, VS output configuration and position format.
PS350 consumes twelve words, emitting program/resources, color/depth export
formats, input configuration, barycentric control and color/depth masks.
A null PS descriptor emits the base-PS4 disabled-PS sequence. VGT emits
IA_MULTI_VGT_PARAM. Trailing NOP payloads are zeroed deterministically.

Guest pointers are never passed to a host driver. All input descriptors are
copied before output, including aliased input/output. Invalid inputs leave
output unchanged. Outputs must be aligned, writable and non-executable.
The maximum copied output is 160 bytes even if advertised capacity is huge.
There is no retained command-writer state or native GPU allocation to reset.

## Indexed PM4 semantics

The interpreter now retains DRAW_INDEX_2, INDEX_TYPE (16/32 bit) and
NUM_INSTANCES in command order. Each draw carries its index address/count,
maximum index count, index size, instance count and preceding register writes.
Invalid alignment, counts, 48-bit addresses, flags or later packets invalidate
the complete stream. These are bounded command semantics; fetching index data
and executing a shader remain renderer responsibilities.

The native triangle diagnostic explicitly refuses indexed/instanced draws
and guest shader state, so adding parser support cannot silently turn a game
draw into the hardcoded native triangle.

## Validation and remaining work

`PS4GnmTest` verifies exact packets, descriptor fields, modifier bounds,
invalid guest memory, atomic failures and aliased buffers. PM4 tests verify
index width, address and instance transitions, invalid streams and unchanged
Metal rejection of unsupported state. The linked FEX fixture calls all five
real GNM NIDs, then checks the resulting VS/PS/VGT state and indexed/automatic
draws from the same engine's memory. Its shader descriptors are fabricated
register values; no shader execution is claimed.

The Sonic GPU backend is **not complete**. Required remaining components:

1. Full command submission and synchronization, including indirect buffers,
   barriers, fences, flip patching and persistent register state.
2. GCN vertex/pixel shader decoding and translation into Metal-compatible
   shaders, with buffer/texture/sampler descriptors and fetch shaders.
3. Render-target/depth formats, tiled memory, blending, viewport/scissor,
   indexed geometry and resource lifetime/coherency.
4. Actual game execution through that backend, pixel validation and physical
   iPhone performance/stability tests.

Neither these command writers nor an offscreen native triangle establish
Sonic gameplay. No IPA or firmware is added by this change.

## Bounded native diagnostic submissions

`sceGnmSubmitCommandBuffers`, `sceGnmAreSubmitsAllowed` and `sceGnmSubmitDone`
now connect to an engine-owned queue. The consumer is detached by default and
after restaging. A submission without a consumer returns the signed GNM
internal-submission error; it does not pretend that GPU work was processed.

The currently attachable consumer is explicitly the existing native triangle
diagnostic. Its shared Metal preflight rejects guest registers/shaders,
indexed/instanced draws and unsupported opcodes. CCB tables are unsupported
and rejected, including non-null zero-filled tables. Submit-and-flip remains
unresolved. No automatic GNM completion events, fences or VideoOut flips are
generated by this queue.

Each submission supports up to sixteen DCBs and 65536 total dwords. There are
four queued submissions. Guest pointer tables (64-bit addresses) and size
tables (32-bit byte sizes) are copied with checked memory reads. Each DCB must
contain complete packets; packet boundaries cannot straddle DCBs. All DCBs
are copied and the combined stream is validated before any job is published.
Changing guest memory after acceptance cannot change queued commands.

`SubmitDone` seals the batch while work is pending. `AreSubmitsAllowed` stays
false until every pending job is explicitly acknowledged, and also returns
false when detached, full or failed. It is not a GPU-idle wait implementation.
The host must call completion only after its Metal command buffer completes
successfully. A failed completion cancels all remaining work and latches a
failure until explicit reattachment or reset. Detach/reset invalidate tickets;
ticket numbers are not reused within an engine. Only the front FIFO ticket
can be completed, and repeated/out-of-order completions are rejected.

The host C APIs are `maxps4_fex_engine_gnm_backend`, `..._gnm_snapshot` and
`..._gnm_complete`. Snapshot returns a 16-byte pointer-free metadata record
and copied dwords. Null words/capacity zero queries metadata; insufficient
capacity leaves the word destination untouched and clears metadata. These
calls use the queue mutex without the global FEX execution lock, allowing
completion while the guest polls. The caller retains the engine and serializes
close; queue operations never expose a guest arena pointer.

Tests cover bounded and malformed metadata, unsupported state, immutable
multi-DCB copies, FIFO/backpressure, sealed batches, failure, stale tickets,
engine isolation and concurrent guest/host work. A synthetic FEX guest calls
the real submission imports and waits for explicit host acknowledgment; this
test alone does not execute GPU work. A separate macOS test runs the real GNM
writer, owned queue, Metal bridge and GPU command completion, then checks red
pixels before acknowledging the ticket. It explicitly skips GPU readback when
no Metal device is available. Neither test executes a PS4 shader or a game.

## Null backend, submit-and-flip and the remaining command writers

The boot probe attaches a third consumer, the null backend (kind 2). It draws
nothing: each decodable submission is retired at once, applying only its
synchronization packets (EVENT_WRITE_EOP, RELEASE_MEM and EVENT_WRITE_EOS
label writes, WRITE_DATA to memory) and triggering registered EOP events.
Waits and constant buffers are ignored. Frames therefore hold only what the
CPU wrote.

`sceGnmSubmitAndFlipCommandBuffers` is accepted by the null backend only.
The last DCB must end with the 64-dword prepareFlip NOP (`0xc03e1000`), as
on hardware; its payload type selects what happens once the flip request
is accepted by VideoOut: nothing, a 32-bit label write, an EOP interrupt,
or both. A missing or unknown packet refuses the submission.

Seven more writers are implemented because Sonic Mania reserves their space
in its DCBs (an unimplemented stub would leave zero dwords there, which the
PM4 framing refuses): `sceGnmSetCsShaderWithModifier`,
`sceGnmDispatchDirect`, `sceGnmSetEmbeddedVsShader`,
`sceGnmInsertWaitFlipDone`, `sceGnmInsertPushMarker`,
`sceGnmInsertPopMarker` and `sceGnmDrawInitDefaultHardwareState350`.
Known gaps: the embedded VS has a null program address (its code is not in
guest memory), the flip-done wait is a same-size NOP (no VideoOut buffer
labels yet), and the 3.50 default state writes only the context clear, not
the register defaults.

## GCN shader decoding

`GCNDecoder.hpp` frames Sea Islands instructions in every encoding family
(scalar, SMRD, VOP1/2/3/C, VINTRP, DS, MUBUF/MTBUF, MIMG, EXP), with
literals, names opcodes and disassembles them. `locateGCNProgram` finds a
Sony-compiled program's bounds the way a GPU backend must at run time: the
prologue `s_mov_b32 vcc_hi, N` puts the OrbShdr binary information at
dword (N + 1) * 2, which records the code length.

`Tools/gcn-shader-inventory.cpp` runs this over a game's shader binaries,
read locally and never committed. On Sonic Mania's 40 `.sb` files every
program decodes with no unknown opcode: 73 distinct instructions, mostly
VALU float math, `v_interp_p1/p2`, `image_sample`, `exp` (with
`v_cvt_pkrtz_f16_f32` compressed colour exports), scalar buffer loads and
fetch-shader calls (`s_swappc_b64`). That set bounds the first translator.
Nothing is translated or executed yet.

## Software GPU backend (first real frames)

`GCNInterpreter.hpp` executes one GCN wave (up to 64 lanes) on the CPU with
real EXEC/VCC masks: scalar and vector ALU, scalar and buffer loads (bounds
from NUM_RECORDS, in STRIDE units when the V# has a stride), linear image
sampling with bilinear filtering, quad swizzles for derivatives,
interpolation from attribute planes, and exports. Code is fetched from
guest memory as it runs, so a fetch shader reached with `s_swappc_b64`
needs no special case. Each sampled texture is copied once per draw.

`PM4SoftwareRenderer.hpp` keeps PM4 register state across submissions and
executes indexed and automatic draws (triangle list/strip, rect list)
through the real vertex and pixel programs: viewport, screen scissor,
rasterization in 8x8 tiles of 2x2 quads with the top-left rule, PS input
VGPRs from SPI_PS_INPUT_ADDR, colour target 0 in 8_8_8_8 UNORM with
COMP_SWAP, target mask and basic blending. Limits: no clipping, depth,
culling or PS4 tiling (targets are written linearly; only the display reads
them), instance 0 only, compute dispatches counted but not run.

GNM backend 3 (software) is the null backend plus this renderer. With it
the boot probe saves Sonic Mania's SEGA logo at 1920x1080: the game's own
CPU-drawn 424x240 screen, scaled by its real `none_vv`/fetch/`none_p`
shaders. It takes about five seconds per frame under the VIXL simulator;
it is a correctness reference for the Metal path, not a playable renderer.
